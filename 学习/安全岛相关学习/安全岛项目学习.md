这个 Safety Island 做的事情是：

> CPU 先通过 AXI 配置它“去哪里检查、多久检查一次、检查哪些 bit”；之后 Safety Island 周期性通过 5 路 AXI Master 去读取外部模块的安全状态寄存器，把读回数据经过 Mask 后做 OR；只要发现异常，就把故障输出锁存起来。同时它还用 TMR、ECC、CRC、Parity、FSM 检查和 Self-test 来保护自己。

# `axi_master_read_engine.v` 输入到底有哪些？

你不要逐根背，分成 4 类就特别简单。

## 第一类：控制输入

```
scan_start_i
enable_i
parity_enable_i
timeout_limit_i
```

分别是：

```
scan_start
    ↓
开始新一轮扫描

enable
    ↓
这一路 Engine 是否工作

parity_enable
    ↓
要不要检查 parity

timeout_limit
    ↓
一笔 AXI Read 最多等多久
```

# 第二类：告诉它“读什么”的配置

```
base_addr_i
offset_addr_i
mask_i
burst_len_i
burst_type_i
offset_enable_i
```

你可以直接记成：

```
BASE          从哪里开始

OFFSET        具体读哪里

MASK          返回的数据哪些bit有意义

BURST_LEN     一次读几个beat

BURST_TYPE    INCR还是WRAP

OFFSET_ENABLE 这个offset到底要不要读
```

# 第三类：AXI AR 通道

这些是 Read Engine **发给外部 Slave** 的：

```
m_axi_arid_o
m_axi_araddr_o
m_axi_arlen_o
m_axi_arsize_o
m_axi_arburst_o
m_axi_arvalid_o
m_axi_arparity_o
```

方向：

```
Read Engine
     │
     │ ARADDR
     │ ARID
     │ ARLEN
     │ ARVALID
     ▼
外部 AXI Slave
```

# 第四类：AXI R 通道

这些是外部 Slave **返回给 Read Engine** 的：

```
m_axi_rid_i
m_axi_rdata_i
m_axi_rresp_i
m_axi_rlast_i
m_axi_rvalid_i
m_axi_rparity_i
```

方向：

```
外部 Slave
     │
     │ RID
     │ RDATA
     │ RRESP
     │ RLAST
     ▼
Read Engine
```

```
fsm_fault_o
```

也就是两大类。

### 正常数据

```
data_o
    ↓
给 data_processor

    ↓

```

### 错误信息


这些最终会送到：

```

```

### DRAIN

`drain` 可以理解成：

> 请求全部发完了，现在等还没回来的 response。

# `free_slot` 是什么意思？

特别简单：

> **当前哪一个 slot 是空闲的。**

例如现在：

```
slot0 active
slot1 active
slot2 free
slot3 active
slot4 free
...
```

组合逻辑扫描后：

```
free_slot = 2
free_slot_valid = 1
```

意思：

> 下一笔 AXI Read 可以使用 slot2。

于是发请求：

```
m_axi_arid_o <= free_slot;
```

因此：

```
ARID = 2
```

同时把这笔 transaction 的信息记进：

```
slot2
```

例如：

```
slot2.mask   = 0x000F
slot2.timer  = 0
slot2.active = 1
```

用slot来记录当前还有哪个RID空闲，然后把RID赋值成free_slot，然后把free_slot赋值给slot，用slot来记录当前这笔读事务的mask、offset等。

`AoU parity` 是：

> **对 AXI 接口上的关键信号额外增加奇偶校验保护。**

CRC：保护“CPU 写配置”的过程

# ECC：保护“配置已经存进去以后”

CPU 正确写入：

```
READ_INTERVAL = 100
```

Safety Island 内部不是只存：

```
100
```

而是：

```
DATA
 +
ECC bits
```

存起来。

假设芯片运行过程中：

```
SRAM / FF
被辐射、软错误影响
```

本来：

```
100
```

某个 bit 翻了。

ECC 可以检测。

这个项目使用：

```
SEC-DED
```

即：

```
Single Error Correction
Double Error Detection
```

简单理解：

```
1 bit坏了
→ 我能发现
→ 而且能修回来

2 bit坏了
→ 我能发现
→ 但修不了
```

所以：

> **ECC = 保护“已经保存的配置数据不要悄悄坏掉”。**


## 1. `system_fault`

它表示：

> **Safety Island 所监控的系统/外部通信出现问题。**

包括：

```
外部安全寄存器报告故障
        ↓
monitor_fault

AXI Read一直不回来
        ↓
timeout

Slave返回SLVERR/DECERR
        ↓
response_fault

AXI数据Parity错误
        ↓
parity_fault

配置操作非法
        ↓
illegal_config_fault
```

代码基本就是：

```
system_fault =
    monitor_fault
  | illegal_config
  | timeout
  | response_fault
  | parity_fault
```

最终对应外部输出：

```
fault_detect_o
```


# 2. `island_fault`

它表示：

> **安全岛自己内部硬件坏了。**

例如：

```
scheduler 三模冗余不一致
        ↓

data_processor 三模冗余不一致
        ↓

Read Engine FSM非法状态
        ↓

配置ECC发现不可纠正错误
```

于是：

```
island_fault = 1
```

对应：

```
safety_island_fault_detect_o
```

所以记住：

```
system_fault
→ 我监控的别人出问题了

island_fault
→ 我自己这个Safety Island出问题了
```


# 3. `latent_fault`

`latent` 就是：

> **潜伏的。**

它不是一定已经导致正常功能出错。

而是：

> 某个本来负责“保护你的安全机制”自己可能坏了。

这个项目包括两个：

```
Self-test mismatch
```

以及：

```
ECC corrected error累计 >= 16
```

产生：

```
latent_fault
```

最后对应：

```
safety_island_latent_fault_detect_o
```
